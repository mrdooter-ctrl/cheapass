Fix Proxmox & Linux 2.5GbE USB Ethernet speed drops

Stuck at 43MB/s or random disconnects? Verify r8152, kill cdc_ncm fallback, and pick cooled RTL8156B silicon.

{{SEASON}}

Adding a second 2.5GbE link to a mini PC running Proxmox VE shouldn't crawl below 1Gbps or drop under ZFS backups. Almost every case boils down to the kernel binding generic cdc_ncm instead of r8152, USB autosuspend, or cheap plastic dongles overheating.

60-second Proxmox / Debian diagnostic

# 1. Confirm you're in a 5Gbps+ USB 3.x port & check active driver (want: r8152)
lsusb -t
ethtool -i enx<your-mac>

# 2. If ethtool shows cdc_ncm or cdc_ether, force r8152 on reboot:
printf "blacklist cdc_ncm\nblacklist cdc_ether\nblacklist r8153_ecm\n" > /etc/modprobe.d/r8152-blacklist.conf
update-initramfs -u
  1. Avoid non-3.x ports: Plug strictly into a blue/SS USB 3.0+ port (USB 2.0 caps around ~350Mbps).
  2. Disable USB autosuspend for high-throughput VM bridges so Proxmox never sleeps the NIC mid-backup.
  3. Swap overheated plastic off-brand sticks for cooled aluminum RTL8156B units (Plugable USBC-E2500 includes an attached USB-A adapter for mini PCs short on USB-C ports).
